# Grammar-oracle contract (Sprint 384, story #1586)

Frozen at checkpoint 1 (2026-10-18). Normative for checkpoints 2–4; change it
only in a reviewed commit made before a candidate is frozen. The plan of
record is the umbrella `docs/sprint-384-master-execution-plan.md` (R1–R6).

## Frozen inputs

- `pin.tsv` lists each frozen input: revision, SHA-256 and license.
  `tools/grammar-oracle/grammar/upstream/` holds the unmodified grammars-v4
  files. Patches start at checkpoint 2, in sibling files, and each one is recorded.
- `manifest.tsv` is generated by `tools/grammar-oracle/inventory.sh`. Never
  edit it by hand. `GOWORK=off go test ./...` in `tools/grammar-oracle` checks
  three things: the inputs are re-derived and their hashes match, the generator
  reproduces the committed file byte for byte, and the pinned files match.
  Sibling repositories resolve from `SH_ROOT` and `BASHSHARP_ROOT`, or else
  from `DHNT_ROOT` (`$DHNT_ROOT/sh`, `$DHNT_ROOT/bashsharp`). There is no
  default: inventory.sh and the tests fail with a clear message when neither
  is set. Sources
  are repo-qualified (`tests:`, `sh:`, `bashsharp:`), with an optional
  `#selector` for an extracted input.

### Manifest columns

`fixture_id lane source sha256 dialect policy class expected boundary reason`

| Column | Values |
|---|---|
| lane | `mixed` (shell and mixed Bash#), `unit` (package-led Go units), `island` (fences and embeds; Go payloads parsed in their own Go lane), `derived` (source-mapped probes and mutants, which earn no whole-unit credit) |
| dialect | `bash` (Bash# off, `sh/syntax` LangBash, as `bash -n`), `bashsharp` (`sh/syntax` LangBashPP), `go-unit` (`sh/gosource` frontend) |
| policy | `sh-syntax`; `gcsyntax` (vendored go1.27.0 compiler parser, the default Go verdict); `goparser` (only where a row selects it explicitly) |
| class | see below |
| expected | `accept`, `reject`, or `-` |
| boundary | expected kind of the input's outermost construct. `shell` means no extension site at all; `go-unit` means one whole Go unit; the other kinds are the `sh/grammar` site rules (`fence`, `embed-line`, `decorator`, `agentic-*`, `typed-func`, `typed-method`, `at-function`, `block`). `-` means the site lists are still compared but no single kind is asserted. |

Classes:

- **required-positive** and **required-negative** (`expected` is `accept` or
  `reject`): blocking.
- **contextual**: the reference verdict depends on frozen non-byte context
  that the `reason` column names (filesystem, aliases, module). `expected` is
  the reference verdict under that context.
- **planned**: syntax that is not shipped (an S6 gap, or a declared planned
  fixture). It is reported but does not block.
- **not-applicable**: never compared. It has no dialect or policy. When
  `sha256` is `-` there are no committed bytes.

New rows enter only through inventory.sh source edits. Once a candidate is
frozen, no row changes class. In particular, a failing required row never moves
to planned or not-applicable.

## Result schema (JSONL, one object per line)

The comparison driver writes one record per expected fixture:

```json
{"fixture_id":"s6/M01","lane":"mixed","dialect":"bashsharp","policy":"sh-syntax",
 "input_sha256":"…","class":"required-positive","expected":"accept",
 "verdict_oracle":"accept","verdict_reference":"accept",
 "boundary_oracle":[{"kind":"typed-func","start":0,"end":41}],
 "boundary_reference":[{"kind":"typed-func","start":0,"end":41}],
 "diagnostics_oracle":[],"diagnostics_reference":[],
 "production_verdict":"accept","transform":null,
 "outcome":"agree","category":"syntax"}
```

- A verdict is `accept`, `reject` or `error`. `error` covers a panic, a
  timeout, an I/O failure or an input hash mismatch, and it never compares
  equal to anything.
- A boundary is a list of extension sites in source order. A span is
  `[start,end)`, measured in byte offsets into the original input. Pure shell
  gives `[]`.
- A diagnostic is `{"offset":N,"line":L,"col":C,"char":K,"msg":"…"}` plus an
  optional `"logical":{"file","line","col"}`. Each side keeps its own actual
  position. The driver never invents a position for a side that accepted.
  Wording is not compared.
- `production_verdict` (gosource only) is the raw production-policy verdict,
  including `CheckBranches` label, goto and branch checks. `verdict_reference`
  is the isolated lexical and grammar verdict, and it is the one compared.
- `outcome` is `agree`, `disagree`, `missing` or `error`. `category` is
  `syntax`, `boundary` or `semantic`.

## Reference adapters (subprocess protocol, R3)

The adapters are package-local test files:
`sh/syntax/grammar_oracle_reference_test.go` and
`sh/gosource/grammar_oracle_reference_test.go`. Neither one adds an exported
production API. Each adapter skips unless `-manifest` is given. The driver
runs each adapter with the pinned toolchain, from the sh root:

```sh
GOTOOLCHAIN=go1.27.2 go test ./syntax   -run '^TestGrammarOracleReference$' -count=1 -timeout 300s -args -manifest M -out R.jsonl
GOTOOLCHAIN=go1.27.2 go test ./gosource -run '^TestGrammarOracleReference$' -count=1 -timeout 300s -args -manifest M -out R.jsonl
```

- `M` is a request TSV written by the driver, with columns
  `fixture_id dialect policy input_sha256 path`. `path` is an absolute path to
  the input bytes. For a whole file, it is the original file, so relative
  embed targets resolve in their frozen directory. For an extracted input, it
  is a materialized copy.
- The adapter checks each input's hash. It writes one reference record per
  request row (`fixture_id`, `input_sha256`, `verdict`, `boundary`,
  `diagnostics`, `production_verdict`, and `phase`, which is `syntax` or
  `context`). It ends with `{"done":true,"count":N}`.
- `sh/syntax` parses the whole input with `Variant(LangBash)` or
  `Variant(LangBashPP)`. It reads sites from the AST extension nodes, in the
  way that `sh/grammar` `compareSites` does. It uses an empty alias
  environment.
- `sh/gosource` reports the verdict from the vendored gcsyntax parser, and
  reports `CheckBranches` in `production_verdict`. Malformed literals, invalid
  bytes and scanner errors count as rejects even when the message has no
  `syntax error` prefix. `Load`'s type checking is never a syntax verdict.
- The driver also enforces a 600 s wall limit. A timeout, a non-zero exit, a
  missing `done` line, a count mismatch, a duplicate or unknown `fixture_id`,
  or a hash mismatch marks every affected fixture `missing`. It is never a PASS.

## Syntax versus semantics

A grammatical verdict is what lexing and parsing alone decide. The following
are never grammar refusals: type checking, undefined names, imports, module
context (`go.mod`), cgo, unsafe layout, embed-target availability,
bridge/module restrictions, null safety, deep `readonly`, contracts,
decorator registration (`EDECO-*`), `lower.CheckBashSharp`/`--check`, and run
exit codes. S6 `exit` values describe fixture execution, not parse verdicts.

Two cases are categorized `semantic` rather than `disagree`: a reference
refusal with `phase: "context"`, and a gosource production-only branch error.
Both are still reported. A syntax verdict must never need PATH, the network,
a model, package downloads or program execution.

## Positions and transforms

- Positions refer to the original input bytes, the ones hashed in the
  manifest. `offset` is a 0-based byte index. `line` is 1-based and only LF
  breaks a line, so in CRLF input the CR stays in the line. `col` is the
  1-based byte column, and `char` is the 1-based code-point column (an invalid
  UTF-8 byte counts as one). Go positions are physical. A `//line` logical
  position is added when it differs.
- Checkpoint 1 inputs need no transform. Polyglot heredocs are the bytes that
  `cat` writes; the `sh/grammar` test's extractor prepends a newline, and that
  form is not used here. Start-site inputs are classify.sh's
  `printf '%b\n'` probe. Divergence inputs are the decoded Go literals.
- Any later change to the bytes a recognizer sees is a transform and must be
  recorded. Examples are appending a newline, wrapping a fragment, extracting
  a fence or embed Go payload, and prepending a `package` clause. The record
  is `{"name":…,"map":[[out_start,orig_start,len],…]}`, and every position is
  mapped back to the original input. A position that falls in synthetic bytes
  is reported at the map anchor with `"synthetic":true`.

## Mutations (bounded, deterministic)

- Mutants are made only from `required-positive` rows whose input is at most
  8192 bytes, taken in manifest order.
- The PRNG is Go `math/rand/v2` PCG, seeded with (384, the first 8 bytes of
  sha256(fixture_id), big-endian).
- Each fixture gets at most 8 mutants, and there are at most 4000 in total.
  Each mutant applies one edit: delete a byte, duplicate a byte, swap two
  adjacent bytes, or insert one token. The insertable tokens are `{`, `}`,
  `(`, `)`, `[`, `]`, `;`, `"`, `'`, a backtick, LF, `~~~`, `:=`, `func`
  and `@`.
- A mutant is a `derived` row with ID `mutant/<fixture_id>/<n>`, and it has
  no authored expectation. Mutants are parsed, never executed. A verdict or
  boundary disagreement on a mutant blocks. It is minimized and then
  committed as a required regression fixture with an authored expectation.
  It is never waived.

## PASS rule

A candidate PASSes only if all of the following hold:

1. **ID sets match.** The result IDs equal, as a set, the expected IDs: every
   manifest row that is not not-applicable, plus the frozen mutant set. No ID
   is duplicated or unknown, and every record's `input_sha256` matches the
   manifest.
2. **Every result is complete.** Each record has both verdicts. An `error`,
   any oracle lexer error, any ANTLR error-recovery event (accept requires
   zero errors under a bail strategy), any unconsumed trailing input before
   EOF, and any `missing` result all fail, whatever the class.
3. **No unresolved required disagreement.** On required rows and mutants,
   `verdict_oracle == verdict_reference`. On required rows that agreement must
   also equal `expected`. When both sides accept, the boundary site lists are
   equal (kind and span), and the outermost kind equals `boundary` unless it
   is `-`. Two recognizers that agree with each other still fail against a
   contradicting `expected`.
4. **Contextual rows hold.** The reference equals `expected` under the frozen
   context. A difference counts only as `semantic`, and only when the
   reference phase is `context`.

Planned and not-applicable rows are reported separately with their reasons.
They neither fail nor count toward a PASS. The disagreement ledger records
each failure: file, offset, line:col, lane, both verdicts and diagnostics. The
ledger never waives a failure.

## Generation and regeneration (remote only)

ANTLR runs only on a claimed remote macOS or Linux host with a JDK path
through the java runner (macOS arm64 or Linux x64), never on the development
machine. The default oracle gate needs only Go, because generated Go is
committed. `tools/grammar-oracle/gen/generate.sh` runs from the development
machine and drives the host over passwordless ssh, in its `zsh -lc` login
environment. `GRAMMAR_ORACLE_HOST` names the host and is required: the script
refuses to run without it, and the name is exported in the operator's shell,
never written into a tracked file.

1. Stage the inputs into a fresh remote temp dir: the upstream grammars,
   `transformGrammar.py`, `go-target/patches/`, `gen/generate.bsh`, and the
   pinned copies `gen/java-runner.sh` and `gen/java-pin.tsv` (#2388, bashy
   `d6dbe6a1`, see `pin.tsv`). The temp dir is always deleted.
2. Fetch `antlr-4.13.2-complete.jar` once into
   `$BASHY_HOME/custom/antlr/4.13.2/`, and refuse it before every use unless
   its SHA-256 equals the `pin.tsv` value.
3. Apply the Go-target transform with the upstream `transformGrammar.py`,
   unchanged, under `python3`. Then apply each local patch
   (`grammar/NOTICE.md`).
4. Register the runner in a private ring, as `examples/runners/README.md`
   does:
   `BASHY_COMMANDS_DIR=<tmp>/ring bashy commands register java-runner --set exec.0=<tmp>/java-runner.sh --set effects.0=exec`.
   An explicit `JAVA_HOME` wins. Otherwise the runner uses the pinned Temurin
   21 cached under `BASHY_HOME` (`JAVA_RUNNER_FETCH=1` fetches and verifies
   it). Any other platform is refused.
5. Run `gen/generate.bsh`, whose `~~~java as gen !java-runner` fence calls
   `org.antlr.v4.Tool.main` with
   `-Dlanguage=Go -no-listener -no-visitor -package goparser -Xexact-output-dir`
   on the bare grammar names. `CLASSPATH` (for javac) and
   `JAVA_RUNNER_CLASSPATH` (for the run) both name the verified jar. The
   transformed grammars go to `grammar/go-target/`, and the recognizer
   (package `goparser`) goes to `tools/grammar-oracle/goparser/` with
   `generated.sha256`. Both are committed, and `GOWORK=off go build ./...`
   must compile them.
6. `gen/generate.sh --check` regenerates into an empty temp dir and runs
   `diff -r` against the committed files, and the diff must be empty.
   `TestGeneratedSums` re-hashes the committed outputs on the development
   machine. The evidence in `grammar/NOTICE.md` records OS and arch, tool
   versions (bashy, Python, JDK), the jar SHA-256, the sums and the exit
   statuses only; never a host name, user name or path.

Checkpoint 1 feasibility passed on 2026-10-19. The unpatched upstream grammar
generated a recognizer that compiled and accepted a Tour of Go unit. Two runs
were byte-identical.

## Oracle recognizer (`tools/grammar-oracle/oracle`)

`oracle.Recognize(lane, entry, src) Result` returns `{verdict, diagnostics}`.
`diagnostics[0]` is the first error, with `offset`, `line`, `col`, `char` and
`msg` as defined under "Positions and transforms". The positions map ANTLR's
code-point columns back to bytes. Only lane `unit` with entry `sourceFile`
exists so far. Any other pair is `error`. The package imports only `goparser`,
the ANTLR runtime (with its `golang.org/x/exp` dependencies) and the standard
library outside `go/...`. `TestIndependentImports` enforces this with
`go list -deps`.

The verdict is `accept` only with zero lexer and zero parser error events and
the input consumed to EOF. The runtime's `BailErrorStrategy` in antlr4-go
v4.13.1 calls `SetError` and records no position. The oracle therefore runs
the default strategy with a listener that records every event. Any event is a
reject, including one the strategy recovered from, so recovery is never an
accept. This is the "bail" of PASS rule 2.

`TestUnitLaneOracle` runs every unit-lane `required-positive` row. It writes
or checks the oracle half of the result records in
`docs/grammar-oracle/results/unit-oracle.jsonl` (`-update` rewrites it). The
records have no reference fields and no `outcome`; the comparison driver adds
those. On accept, the oracle boundary for a go-unit is
`[{"kind":"go-unit","start":0,"end":len}]`. `docs/grammar-oracle/findings.tsv`
is the ledger of every oracle disagreement with an authored expectation. A row
is `open` or `fixed:<patch>`. The tests require each disagreement to be an
open row at its first-error offset, and each fixed row to agree. The ledger
never waives a PASS-rule failure.

Checkpoint 2 unit lane: 184 required-positive rows, oracle accept 184,
reject 0, expected accept 184. One real finding,
`gbe/pointers/pointers.bsh` (`new(42)`, offset 1261, 45:11), was fixed by
grammar patch 0001.

## Go predicate audit (R6)

The upstream parser base supplies these predicates: `isOperand`,
`isConversion`, `isMethodExpr`, `isTypeArgument`/`isExpressionArgument`,
`isNotReceive` and `closingBracket`. `isOperand` and `isMethodExpr` consult
`addImportSpec`'s import-name table. The audit units are in
`tools/grammar-oracle/testdata/go/`. A `neg-*` file is a gcsyntax syntax
reject; every other file is a gcsyntax accept. Each expectation was confirmed
with `go tool compile` (go1.27.2: `syntax error` or none), and
`TestPredicateAudit` cross-checks it with go/parser outside package oracle.
Outcome:

- **Import-name table (`addImportSpec` → `isOperand`).** The table is
  unsound. It records the last import path element after its last dot (`v2`,
  `v3`), not the package name, and a local name that shadows an import is
  never removed. With `x` absent from the table, `x.T{…}` was refused.
  Patch 0002 takes the table out of every verdict: `operand` is always
  viable. The table now feeds only `isMethodExpr`, which returns true for
  every identifier whether or not it is in the table, so it decides nothing.
  Units: `import-versioned-complit`, `import-dotted-complit`,
  `import-renamed-complit`.
- **Aliases (`aliases`).** Plain and generic aliases work as composite-literal
  types, conversions and method-expression receivers. They passed with and
  without the patches.
- **Generics (`generics`).** Instantiated composite literals, calls,
  conversions and method expressions, plain and package-qualified (including
  `rand.N[int64]` behind a versioned import), all pass.
- **Conversions (`conversions`).** `isConversion` is a pure token test (not
  an identifier). Identifier and qualified conversions parse as an operand
  followed by a call. All the type-literal conversions pass.
- **Method expressions (`method-exprs`).** `T.M`, `(*T).M`, `time.Time.Unix`
  and `(*time.Time).Unix` pass. A value receiver `t.M` parses as a selector,
  which has the same tokens.
- **`make`/`new` (`builtin-new-make`, `type-first-arg`).** The predicates key
  on the token text. They refused Go 1.26 `new(expr)`, methods named `make`
  or `new`, and a Type first argument to any other call, which the spec
  syntax admits. Patch 0001 replaces them with the spec production.
- **Negatives.** `neg-method-expr-name`, `neg-conversion-unclosed`,
  `neg-make-empty-arg`, `neg-new-two-types` and
  `neg-generic-qualified-complit` are rejected, as gcsyntax rejects them.
- **Composite literals in control headers (`neg-complit-in-if`, fixed by
  patch 0003).** The grammar over-accepted `if x == T{} {`. It lacked the
  spec's composite-literal parsing-ambiguity rule, which gc implements with
  `xnest` control-clause state. Patch 0003 guards the bare-TypeName
  alternative of `literalType` with the `compositeLitOK` predicate, which
  reads that state from the rule-context chain (an enclosing bracket, brace,
  parenthesis or case clause admits the literal; an `if`/`for`/`switch`
  header refuses it). Units: `complit-in-headers` (accept),
  `neg-complit-in-if`, `neg-complit-in-for`, `neg-complit-in-switch`,
  `neg-complit-in-else-if` (reject). `findings.tsv` has no open Go row.
- `isNotReceive` (`chan<-` versus `chan (<-chan T)`) and `closingBracket`
  (an omitted `;` before `)`/`}`) have no table dependency. They are
  exercised by the 184 unit rows.
